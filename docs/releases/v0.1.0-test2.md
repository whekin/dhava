# Nakvali 0.1.0-test2 — Android preview

This is an experimental Android 14+ release for field testing. The APK is
signed with the existing Nakvali release certificate and contains no private
Nakvali alpha API access key.
The first authenticated sensor-metrics request from this build has not yet been
verified end to end against BIKEYARD.

- Airtime candidates are visible on the ride map at overview and detail zoom,
  with per-event timing and phone-sensor peaks. These are not validated jumps
  or rider body-force measurements.
- BIKEYARD receives processed TCX.GZ rides. A separate, default-off option can
  send candidate airtime timing and measured sensor availability for **new
  private rides** after their track import completes. One private ride can also
  be sent manually from its export sheet.
- Raw GPS/IMU/barometer recordings stay on the phone. Sensor-metrics documents
  contain no GPS coordinates, raw IMU samples or phone G peaks.

In **Profile → BIKEYARD**, connect your account, choose **Only me**, enable
automatic ride uploads, then opt into **Experimental airtime** and select where
you carry the phone. The experimental switch starts off. Existing rides already
uploaded by earlier builds cannot attach metrics because their original track
section boundaries were not retained.

This public APK omits the owner's private Nakvali backend access key. Local
recording and direct BIKEYARD integration remain available; owner-only backend
profile sync may be unavailable. Keep a backup of rides you want to preserve.
